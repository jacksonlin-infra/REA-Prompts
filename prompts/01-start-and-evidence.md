# 入门、范围与证据管理

**简体中文** | [English](01-start-and-evidence.en.md)

[返回总目录](../README.md)

适合第一次调查、恢复调查或准备可交接的结果。每条代码块可独立复制，以具体问题和可核验成果为中心。

本页中的“当前项目”与“输出目录”指你的调查工作目录，不是 REA 源码仓库；没有现成项目时可指定一个新目录。“保存”指写入该目录；会话内 Evidence ID 不保证跨进程仍可读取。

## A01

**交互式入门向导（跨客户端）**

```text
请作为我的 REA 调查助手，用中文解释。先读取当前项目已有的 REA-TASK.md（如果存在），核对其中目标路径、版本和摘要是否仍对应本次任务。
从对话已有信息中确定：目标是什么、在哪里、要解释哪个功能、期望产出是解释/规格/最小实现。只询问缺失且会阻碍工作的内容；不要自行选择示例软件或扫描整块磁盘。
检查当前客户端的 REA 连接和目标相关能力。已有可用能力就开始；需要修复配置时先展示 setup 计划。不要因无关的原生引擎缺失而阻塞 JavaScript 等独立路线。
将问题、目标身份、允许的动作、证据位置和下一步写入 REA-TASK.md。先追踪一个功能，提交有证据的解释；只有我选择了实现，才在指定新目录编写实现。

默认只做静态分析，不运行目标。每项结论引用 Evidence ID 和源位置，区分观察、推导、推测与未知，并说明覆盖缺口。

优先使用现有 REA 工具；没有入口时用 npx -y rea-agents@latest --help 确认可用命令。仅在任务确需配置变更时展示计划并获批；无法继续的部分说明具体阻塞。
```

## A09

**审查尚未解决的问题**


## A11

```text

列出真正矛盾、观察条件不同、解释不同三类情况，提出最小补证计划。
```

## A12

**分析被截断或工具不可用时继续**

```text
使用 REA 继续 <当前问题>。先读取失败原因或覆盖说明，判断是输出传输限制、分析预算、工具未配置、宿主不支持还是目标不支持。
有 retained Evidence 时，按返回的 parent_evidence_id 使用 inspect_analysis_view 获取相关摘要或页面；不要反复执行同一个失败调用。
没有对应能力时，完成独立可做的分析，并明确列出剩余条件。不得把截断预览当成完整 JSON 或完整搜索结果。

引用 Evidence ID、输入身份和覆盖范围；区分观察、推导、推测与未知，不把缺失记录当作不存在。
```
